# 抖音公开文本采集 Spec v0.1

日期：2026-11-12（Asia/Shanghai）

交付对象：开发 Agent

状态：待实现；本文不代表已经完成采集或验证检索词效果。

## 1. 目标与完成条件

开发一个用于小样本研究的抖音公开文本采集模块。用户配置关键词，创建采集任务，获得可去重、可追溯、可人工复核的内容，并能比较各检索词带来的有效线索。

最小闭环：

> 导入关键词 → 创建任务 → 采集公开文案 → 去重入库 → 文本候选分类 → 人工复核 → 按词统计 → 导出。

用户明确要求省去视频理解。整个闭环不得依赖视频下载、音频下载、语音转写、画面抽帧、OCR、多模态模型或人工观看视频。原始作品链接可供用户自行打开，观看不属于验收前提。只有视频中才出现的信息记为本版本的覆盖限制。

## 3. 技术与项目边界

- 在现有仓库新增独立的 `collector/` 模块。本次实现的业务范围仅限该模块。
- 后端采用 FastAPI、SQLAlchemy 2、Alembic；数据库采用 MySQL 8，使用独立逻辑库 `douyin_intel`，可复用已有 MySQL 实例。
- 一个 API 进程、一个独立采集 worker 即可。任务保存在数据库；本期不引入 Redis、Celery、Kafka 或微服务拆分。
- 操作入口使用 FastAPI 的 `/docs` 和 HTTP API，导出后可在表格工具中复核。本期不要求另建前端。
- 采集层通过 `DouyinCollectorAdapter` 封装。复用 MediaCrawler 的搜索、作品解析、评论采集能力，避免让业务层依赖其内部字段和全局变量。
- 开发时固定 MediaCrawler 版本；为每个任务生成独立配置快照。禁止通过覆盖共享配置文件切换任务参数。
- 提供脱机 fixture 适配器供验证使用；真实采集失败时不得自动切换为 fixture 并显示成功。

MediaCrawler 已核对的参考版本为 `306ab4ca26c0e44fb87ede0e40e98748752815a6`。该版本采用 **NON-COMMERCIAL LEARNING LICENSE 1.1**；复用时保留版权与许可声明，按非商业学习研究范围交付，不把它标记成 MIT 或 Apache 许可。

| 主题键 | 主题 | 初始检索词，逐条独立执行 |
| --- | --- | --- |
| interaction | 互动与流量 | 涨粉、互动提升、直播间人气、粉丝增长、账号引流 |
| account_operation | 账号运营 | 养号教程、矩阵运营、多账号管理、账号运营、账号权益 |

以上 20 个词均为待验证种子词，不预设强弱等级或命中率。第一轮计划每词最多 20 个不同作品 ID，最多形成 400 条“关键词—作品”关联，去重后的作品数量可能更少。

首轮词表由用户导入后创建任务；不因安装或启动服务而自动执行。发现新表述后可人工新增词，再创建新的任务。空结果不触发自动生成暗语或组合词。

## 5. 任务参数与配额

示例请求配置：

```json
{
  "keyword_ids": [1, 2],
  "limit_per_keyword": 20,
  "max_pages_per_keyword": 2,
  "publish_window": "unlimited",
  "sort": "general",
  "comments": {
    "enabled": false,
    "max_posts": 10,
    "max_per_post": 20
  }
}
```

- `keyword_ids`：1～20 个启用的词；创建时冻结词文本、主题与任务配置，之后修改词表不改变已有任务。
- `limit_per_keyword`：默认 20，范围 1～20；`max_pages_per_keyword`：默认 2，范围 1～3。
- 每个任务最多 400 个不同的“关键词—作品”关联；同一作品跨词出现分别消耗各词配额，但内容只存一份。
- `publish_window` 本期只接受 `unlimited`、`one_day`、`one_week`、`six_month`；保存实际传给采集器的值。
- `sort` 本期只接受 `general`。MediaCrawler 底层存在其他排序枚举，但参考版本的搜索调用没有显式传入排序参数；未完成适配验证前不能在 API 中宣称支持。
- 对本模块主动发出的平台请求统一串行限速，默认请求起点间隔至少 3 秒；评论请求与重试同样计入。
- 单请求超时默认 20 秒；可重试的超时、连接中断、5xx 最多额外重试 2 次，等待 5 秒、15 秒，并遵守服务端要求的更长等待。
- 认证、验证挑战、403/429 等访问限制进入 `blocked`，保存原因与已完成进度，不持续重试。

每词达到结果配额、页数上限或服务端明确结束后停止该词。记录 `stop_reason` 为 `quota_reached`、`page_limit` 或 `source_exhausted`。达到页数上限不能解释为已经搜尽。

评论关闭时不请求评论接口。评论开启时，在搜索结束后，从本任务规则优先级最高的候选作品中最多选择 10 个，按优先级、发现时间、作品 ID 稳定排序；每条最多保存 20 条一级评论，不采二级回复。参考版本按接口返回顺序获取评论，不将其标注为“热评”。评论阶段也使用独立进度记录，阻塞和取消均能生效。

## 6. 采集内容与性能约束

### 6.1 作品字段

必需字段：`platform=douyin`、`content_id`、`source_url`、`description`、`published_at`、`first_seen_at`、`last_seen_at`。

按来源可用性保存：`hashtags`、`creator_hash`、`like_count`、`comment_count`、`share_count`、`collect_count`。缺失值存 `null`，不伪装成 0；互动计数不能用于推断实际成交或攻击效果。

MediaCrawler 参考版本的 `title` 与 `desc` 均来自 `aweme_item.desc`。本模块统一保存 `description`，不把它们拼接成两份文本，也不把文案称作视频字幕。话题优先使用明确的结构化字段；如果只从 `#话题` 文案中解析，应标注来源为 `parsed_description`。

缺少作品 ID 的条目记入解析失败统计，不生成假的作品 ID。文案为空的作品仍可保存元数据，但标记 `text_status=empty`，不补造文本、不自动转向视频分析。

### 6.2 评论字段

保存评论 ID、所属作品 ID、文本、发布时间、匿名作者标识、点赞数、采集时间。评论证据必须独立记录作者，不能将评论者的宣传或询问归到作品作者名下。

### 6.3 只处理文本

- 固定关闭 MediaCrawler 媒体下载与词云开关：`ENABLE_GET_MEDIA=False`、`ENABLE_GET_WORDCLOUD=False`。
- 默认关闭 `ENABLE_GET_COMMENTS`、固定关闭 `ENABLE_GET_SUB_COMMENTS`；仅在本任务明确开启评论时执行受配额限制的补采。
- 不打开播放页执行自动播放，不主动请求视频、音频、封面或图文图片文件；浏览器人工登录所需资源正常加载。
- 不运行转写、OCR、图像模型或文本大模型。候选分类只使用本地文本规则，禁止为每条内容串行调用外部模型。
- 搜索结果已有足够字段时不再逐条请求作品详情。只有必需字段缺失才补采，详情补采每任务最多 10 次，并受相同限速和阻塞控制。

## 7. 数据关系与幂等性

最少表达以下实体，具体表名可调整，但唯一约束和关联必须保留：

| 实体 | 核心约束 |
| --- | --- |
| Keyword | 规范化检索词唯一；主题可多选；保留原文 |
| Job | 配置快照、运行状态、阶段、计数、起止时间、采集器与规则版本 |
| JobQuery | 每任务每词一条；保存词快照、请求游标、下一页、配额、状态与停止原因 |
| Content | `(platform, content_id)` 唯一；更新计数和最近发现时间不新增作品 |
| Discovery | `(job_query_id, content_id)` 唯一；保留首次发现页、位置与时间 |
| Comment | `(platform, comment_id)` 唯一；关联作品与评论采集进度 |
| Assessment | 规则版本、文本版本、建议体裁、候选风险标签、逐条原文证据 |
| Review | 人工相关性结论、修订标签、理由、时间；保留历史记录 |

作者按稳定的 `creator_hash` 分组；不通过脱敏昵称合并作者。不提取联系方式，也不将内容相似作为同一作者的证明。

一页响应经校验后，在同一数据库事务中提交内容、来源关联和下一页进度。提交失败不推进进度；提交后崩溃再次执行时依赖唯一约束消除重复。同一关键词下重复出现的 ID 不重复消耗配额。相同作品被另一个词命中时新增 Discovery，不覆盖原检索来源。

保留原文。非空规范化文本可计算指纹并标记相似内容组，但不得删除不同作品 ID 的记录。空文案不进行相似分组。

文案内容变化时产生新的文本版本，旧评估和复核继续保留，新版本进入待评估／待复核状态。互动数字变化不使文本复核失效。

## 8. 任务状态、失败和恢复

任务状态：`queued`、`running`、`blocked`、`interrupted`、`completed`、`failed`、`cancelled`。任务阶段至少区分 `search`、`comments`、`analysis`。

- API 只入队，worker 执行；任务和进度不能仅放在 FastAPI 的内存后台任务中。
- 全局同一时间只允许一个 worker 拥有有效执行权。多次启动 worker 或重复操作不能造成任务重复采集；使用数据库执行权租约与条件更新，保证旧执行者失去租约后停止请求和写入。
- worker 保存心跳。异常退出后，将租约过期的运行任务标记为 `interrupted`，保留已提交进度；用户显式恢复后从未完成页继续。
- 用户取消后，当前正在进行的一次请求可以完成；之后停止新增请求，已提交数据保留，显示 `cancelled`。取消不伪装成完整采集。
- 可重试错误耗尽后将对应查询标记失败，其他词可继续。任务结束时如果存在失败查询，最终任务为 `failed`，附带已成功查询和部分数据，不整体清空。
- 认证、验证或访问限制使整个任务 `blocked`；人工处理后显式恢复，不切换身份继续。
- 只有来源成功响应、符合预期结构且明确返回空列表，才能记为 `empty_result`。`data` 缺失、登录页、错误页、无法解析的内容都不能记为“搜不到”。
- `completed` 表示全部查询按配置上限正常结束，且启用的评论、分类阶段已结束；它不表示获取了平台全部相关内容。

## 9. 文本分类与 BREAK 映射

输出分成三个独立字段：

1. `content_type`：`service_ad`（服务宣传）、`tutorial`（教程）、`tool_intro`（工具介绍）、`complaint`（投诉求助）、`governance_case`（治理案例）、`education`（科普）、`ordinary`（普通内容）、`uncertain`。
2. `candidate_risk_ids`：可为空，可多选；每个标签必须有对应原文证据。
3. `review_relevance`：`pending`、`relevant`、`irrelevant`、`uncertain`，由人工复核填写。

规则用于排序与候选归类，不能证明攻击已发生。规则文件至少包含 `rule_id`、`version`、适用体裁、必要表达、排除／否定语境与优先级。命中记录保存作品或评论 ID、原文片段、起止字符位置和规则 ID。位置使用相应文本版本原文的 Unicode 字符索引，不使用浏览器渲染后的截断文案。

必须覆盖的分类示例：

- “介绍云手机如何管理账号”：可归 `tool_intro`；只凭工具名不产生设备绕过、虚假注册标签。
- “警惕刷单骗局”：可归 `education`；不能归为发布者提供刷单服务。
- 明确宣传虚假点赞等服务：可归 `service_ad`，将相应语句作为 `R0016` 刷量刷榜的候选证据，保留待人工复核状态。
- 评论表达“怎么买”：仅为该评论的询问信息，不证明成交，也不证明视频作者售卖。
- 无文本或语境不足：`uncertain`，风险标签可为空。

BREAK 参考固定为 `break-risk-intel-skill@11e2e502f19d77aedc9989fdafb6b9032cc0cada` 中的 `BS05`。本期按需使用已核对的 `R0016` 刷量刷榜、`R0034` 自动化养号、`R0017` 虚假交易、`R0056` 虚假评价等风险项；没有足够证据时不强制映射。

风险编号与名称从 `references/risk-index.md`、`scenes/short-video-live.md` 核对，保存来源文件与版本。不能直接照搬示例报告中的编号；发生冲突时保留未映射并说明原因。该版本的 `BS05` 与当前上游 `BD05` 不混用。

人工确认“与研究主题相关”不等于确认作者实施违法行为。结果表达为公开内容线索，允许相关但不对应具体风险编号。

## 10. HTTP API 与使用路径

| 方法和路径 | 行为 |
| --- | --- |
| `POST /api/keywords/import` | 校验并导入 CSV，返回新增、合并、无效词及逐行原因 |
| `GET /api/keywords` | 查询词、主题、启用状态 |
| `PATCH /api/keywords/{id}` | 修改启用状态、主题与来源，不回写已有任务快照 |
| `POST /api/jobs` | 校验配置并创建 queued 任务，不等待采集结束 |
| `GET /api/jobs`、`GET /api/jobs/{id}` | 分页查看状态、阶段、每词进度、停止原因与错误 |
| `POST /api/jobs/{id}/cancel` | 幂等取消请求 |
| `POST /api/jobs/{id}/resume` | 恢复 blocked、interrupted、failed 的未完成部分；其他状态返回冲突 |
| `GET /api/contents` | 按任务、关键词、主题、体裁、风险项、复核状态分页筛选 |
| `GET /api/contents/{id}` | 原文、全部发现来源、候选证据、评论与复核历史 |
| `POST /api/contents/{id}/reviews` | 提交相关性、体裁、风险项与理由；必须指定文本版本 |
| `POST /api/reviews/import` | 导入导出表中的人工复核列，按 ID 和文本版本幂等处理 |
| `GET /api/jobs/{id}/keyword-metrics` | 每词指标，带分子、分母及统计时间 |
| `GET /api/jobs/{id}/export?format=csv\|jsonl` | 按作品导出，一条作品一行，携带多个命中词及复核字段 |

分页默认 50 条、最多 100 条；不允许无界查询。评论开关、配额等只在创建任务时设置，恢复使用原快照；修改配置应新建任务。

导出含 `content_id`、`text_version`、原始链接、文案、发现词、主题、体裁、候选风险、证据、人工结论和采集时间。CSV 使用 UTF-8 BOM，正确处理换行、逗号与公式前缀。人工复核导入只允许更新复核列，不能修改来源和原文；版本过期的行明确拒绝。JSONL 保留结构化数组和原始字符串值。

## 11. 关键词效果统计

按本任务、每关键词分别返回：

| 指标 | 定义 |
| --- | --- |
| 原始返回条目数 | 成功处理并提交的搜索页中的条目数量；重试同页不重复累计 |
| 有效作品数 | 该词关联的不同有效作品 ID 数 |
| 同词重复数 | 有效返回条目中同一 ID 在该词内的重复次数 |
| 跨词共享数 | 同任务中同时被其他词命中的作品数 |
| 独有作品数 | 本任务内仅被该词命中的作品数，与词的执行先后无关 |
| 首次发现数 | 采集时首次进入整个内容库的作品数；注明其受执行顺序影响 |
| 已复核数 | 有当前文本版本人工结论的不同作品数 |
| 相关／不相关／不确定数 | 已复核内容的三个分项 |
| 复核覆盖率 | 已复核数 ÷ 有效作品数 |
| 有效线索率 | 人工标记 relevant 的数量 ÷ 已复核数；不确定项计入分母并单列 |
| 独有有效线索数 | 该词独有作品中人工标记 relevant 的数量 |

分母为 0 时返回 `null`，显示“未采到作品”或“尚未复核”，不能显示为 0% 有效率。词级统计允许同一作品计入多个词，全任务汇总按作品 ID 去重；不能把词级数量直接相加成唯一内容数。

保存每页提交标识以支持原始返回计数幂等。指标依据当前版本人工复核结果计算，并显示待复核与不确定数量。该统计只用于比较此次检索表现，不推断风险在抖音上的发生率或完整覆盖率。

## 12. 验收标准

使用有明确预期的合成响应验证以下行为；核心幂等、执行权和恢复场景必须在 MySQL 8 上验证，不能只依赖内存对象或 SQLite：

| 编号 | 输入或操作 | 必须满足的结果 |
| --- | --- | --- |
| A01 | 同一作品被两个词返回，同一词下一页再次返回 | 一份 Content、两份 Discovery；同词重复不消耗新的作品配额 |
| A02 | 同页提交后崩溃，恢复时重复获得该页 | 内容、关联、原始页计数均不重复；继续未完成页 |
| A03 | 处理页面时数据库提交失败 | 内容与进度同时回滚，不跳过失败页 |
| A04 | 服务端一页返回超过剩余配额的内容 | 保存不超过配额的有效作品；明确 quota_reached |
| A05 | 成功空响应、登录页、结构变化、403、超时分别出现 | 区分空结果、解析错误、blocked 和重试耗尽，不全部当作空结果 |
| A06 | 两个 worker 同时启动，或旧 worker 租约失效 | 只有有效执行者采集和写入；不重复执行同一任务 |
| A07 | 搜索或评论阶段取消、进程退出后恢复 | 及时停止后续请求，保存进度；恢复不重做已提交部分 |
| A08 | 默认配置；再开启评论并制造超过预算的候选 | 默认无评论请求；开启后最多 10 条作品、每条最多 20 条一级评论 |
| A09 | 在采集器调用和输出目录记录媒体行为 | 无媒体下载调用、无媒体文件、无 ASR/OCR/模型调用；不重复请求已有完整作品详情 |
| A10 | 云手机介绍、反诈科普、服务宣传、普通评论、空文案 | 按第 9 节区分；不凭工具名或检索词直接认定风险 |
| A11 | 同名作者、脱敏后同名作者、同作者不同昵称 | 使用 creator_hash 分组，不按昵称错误合并 |
| A12 | 零复核、混合复核、跨词重叠数据 | 指标按第 11 节计算，可核对分子分母，零分母为 null |
| A13 | 导出含换行与特殊字符的文案，再导入复核 | 无列错位、不执行公式；过期文本版本拒绝，原文不被覆盖 |
| A14 | 不同任务先后修改关键词、规则、计数及文案 | 快照可复现；纯计数变化不使复核失效，文案变化需要新版本复核 |

真实联调另做小样本：操作者完成正常登录后，选择 2 个词、每词最多 10 条、评论关闭。核对原始链接、文案和来源关系；再按需对 1 条作品补采评论。记录执行时间、请求次数、错误及媒体下载次数，不预先承诺命中率或平台响应速度。

真实联调无法访问时标注具体阻塞点；脱机测试通过不能写成真实抖音采集成功。本文编写阶段未执行真实抖音搜索。

## 13. 开发顺序与交付清单

1. 建立模块、数据库迁移、词表与任务模型，完成 fixture 下搜索入库、去重和来源关联。
2. 接入固定版本采集器，实现限速、配置隔离、错误分类、进度持久化与恢复。
3. 实现轻量文本候选分类、人工复核、指标与导出。
4. 补充受配额控制的可选评论采集。
5. 完成行为验收与小样本真实联调，报告已通过、失败与未验证项。

交付必须包含：可运行代码、依赖锁定、迁移、20 词种子 CSV、任务示例、版本化规则与风险字典、脱机 fixture、测试结果、启动及正常登录说明、词表导入到导出的一组完整操作示例、许可说明和已知覆盖限制。

不得用硬编码的演示结果替代真实适配器，也不得为了让示例看起来完整而补造评论、字幕、风险标签或搜索结果。
