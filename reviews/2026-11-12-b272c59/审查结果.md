## 确认的功能问题

### R1 [P2] 输入合法间隔会被逐键钳制为其他值

- 位置：`src/App.jsx:149`。
- 路径：键盘输入 → onChange 每次 parseInt 并立即限制到 500–30000 → 受控 value 覆盖输入 → intervalMs 更新 → effect 重建定时器。
- 复现：全选间隔框，逐键键入 `1000`。第一个字符 `1` 被立即替换为 `500`，后续字符在替换后的文本上继续输入，最终得到 `30000`，而非期望的 `1000`。
- 影响：常规键盘修改无法可靠设定合法间隔；运行中编辑也会不断改变正在执行的注册频率。
- 建议：用独立字符串保存编辑中的值，在失焦或确认时校验并提交；对每轮账号数控件使用同样的编辑策略，保留明确的范围提示。
- 验证：`behavior-results.json` 中对应浏览器 Case 失败，实际值为 `30000`。直接 `.fill('1000')` 只发送完整值，不能覆盖逐键输入路径。

### R2 [P2] 独立随机组合设备指纹会产生不可能的设备

- 位置：`src/mockData.js:69–85`。
- 路径：独立抽取 model、os、browser → 依据 os 推导 platform/arch → generateRegistrationBatch 直接引用设备对象 → 注册数据与日志。
- 复现：固定随机种子的资源库中，出现 `iPad Air 5 + HarmonyOS 4 + Linux arm64`、`MacBook Air M2 + Android 12`；检查出的 Apple 设备不兼容组合有 15 台。
- 影响：用这些记录演示或测试防守端时，不可能的指纹组合会引入与出口复用无关的异常信号，掩盖网络关联实验。型号池还包含笔记本，与原始“100 台真实手机”的约束不一致。
- 建议：按设备族生成兼容的 OS、浏览器、平台、架构和 GPU 等字段；若坚持 100 台手机的需求，应使用手机型号池。
- 验证：独立领域约束 Case 失败；没有把随机字段的具体取值作为预期，只检查 Apple 型号与系统是否兼容。

### R3 [P2] 随机排序产生明显的 IP 位置偏差

- 位置：`src/mockData.js:119`。
- 路径：随机比较器 sort → 取前 distinctCount 个 IP → 批次内随机抽样 → IP 注册频率。
- 复现：固定种子运行 24000 轮、每轮 1 条、复用强度 100%，12 个 IP 本应没有数组顺序导致的偏好。第一个 IP 被选中 4027 次，最低仅 1298 次，最大/最小为 3.10 倍；每个 IP 的均匀期望约为 2000 次。
- 影响：资源数组顺序在控制参数之外引入流量热点，影响用复用强度比较网络关联的实验。随机比较器也不满足排序比较器的一致性要求。
- 建议：使用 Fisher–Yates 洗牌或直接进行无偏的无放回抽样，保留原有 IP 子集大小规则。
- 验证：确定性种子统计 Case 失败；测试容忍最大/最小比小于 1.5，并非要求有限样本中计数完全相等。

### R4 [P2] 日志剥离时区后把 UTC 当作无标记时间展示

- 位置：`src/mockData.js:115`；消费位置 `src/App.jsx:201`。
- 路径：Date → toISOString（UTC）→ 去掉 T、毫秒和 Z → createdAt 无时区字符串 → slice(11) 仅显示时分秒。
- 复现：浏览器时区 Asia/Shanghai，本地时间 `17:00:12`，界面显示 `09:00:12`，日志区没有 UTC 提示。
- 影响：用户无法判断时间基准，和本地事件对照会错位 8 小时；跨时区解析该 createdAt 字符串还会产生歧义。
- 建议：记录中保留完整 ISO 8601 时间；显示时按浏览器本地时间格式化，或明确标注使用 UTC。
